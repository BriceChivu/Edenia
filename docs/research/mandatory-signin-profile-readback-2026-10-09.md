# Keep local readback acknowledgment out of external profile refresh

A focus refresh can read an IndexedDB head after a local transaction commits but before the writer completes its independent readback. The repository treated that head as another writer's update and notified the application. In the signed-in trial, that notification reopens the profile, retires the current activation and makes the original write fail its activation fence. Its exact unacknowledged head is then rolled back, and concurrent cloud requests can leave the interface in protected recovery. Native Safari reached that recovery state while background refreshes were running; the narrow commit/readback interleaving was reproduced independently with the actual repository in Chromium and WebKit.

The repository now recognizes the exact physical heads of its unacknowledged local full-profile and island-checkpoint writes. A refresh that observes one leaves acknowledgment and any rollback to its writer. Tracking ends when the write settles. Independent commit readback, access-value and activation fences, rollback conditions, and normal external update notifications remain unchanged. A newer external winning head is still adopted, cancels the older writer and survives reload. Island contents remain opaque; this is Edenia persistence behavior, with no gameplay change.

Deterministic browser tests hold the writer's completed readback, dispatch focus and finish the resulting read before releasing acknowledgment. Both full-profile and island cases failed before the repair in both engines. The newer-external-winner control passed before and after it. All six cases pass with the repair. All 60 focused Chromium/WebKit repetitions, all 58 complete IndexedDB-profile browser cases and all 1,913 client contracts pass. The normal build and explicit `node scripts/build-experience-tiny-swords.mjs --project godot/tiny-swords` preview rebuild also pass. CI and hosted acceptance follow this local checkpoint. Private profiles and hosted diagnostic receipts remain outside Git. This continues issue #177 within the admitted-owner mode-1 trial; public mandatory entry and migration cutover remain outside scope.
